KỊCH BẢN TEST - 5 REST API TẠO LEAD (SALESFORCE - BUV)
========================================================================
Công cụ test: http://localhost:3000/lead-api-tester (Next.js proxy)
Org: DEV sandbox (buv-crm--dev2.sandbox.my.salesforce.com)

Dữ liệu master đã xác nhận tồn tại trên org DEV (dùng đúng các giá trị này,
nếu gõ sai sẽ bị Validation Rule chặn hoặc Apex lỗi "List index out of bounds"):
  - Province__c mã đúng duy nhất: "Hồ Chí Minh" (có dấu)
  - Group_Programme__c: Undergraduate, English, Pathway, PostGraduate (đã tạo qua SF CLI để test)
  - Campus_Group__c: "British University Vietnam" (đã tạo qua SF CLI để test)
  - Lưu ý: 2 dòng trên là dữ liệu TẠM để test, cần hỏi Dev Lead/BA có giữ lại không.

Quy tắc Validation Rule "API_Gate1_Required_Fields" (chỉ áp dụng khi isAPI__c = true):
  Chặn nếu THIẾU 1 trong 6 field: Email, MobilePhone, You_are__c, DOB__c,
  City_Province__c (map từ City_or_Province__c), LeadSource.
  (Field "LastName" không nằm trong rule này nhưng Lead luôn cần LastName để insert
  được vì đây là Name field bắt buộc của object Lead).

Flow "Lead_Auto_Assign_RecordType" (Active): tự động gán RecordType theo You_are__c:
  - You_are__c = "Student"  => RecordType = Student
  - You_are__c = "Guardian" => RecordType = Guardian
  - Các giá trị khác (Parent, Working people, BUV Alumni) => giữ RecordType mặc định, không đổi.

LƯU Ý RIÊNG cho APILeadPostgraduate:

tạo lại record Group_Programme__c với tên khác (vd "Postgraduate" không hoa G),
API sẽ lỗi "List index out of bounds" ngay cả khi payload đúng.

Mục đích: xác nhận API từ chối đúng khi token sai.

"authorizationpermanent" điền giá trị random -> kỳ vọng HTTP 200 nhưng
body trả về Message = "The token invalid", errorCode = 401, Lead KHÔNG được tạo.
(Không test được qua UI /lead-api-tester vì UI luôn gắn đúng SF_LEAD_TOKEN)

GHI CHÚ CHUNG KHI TEST QUA UI /lead-api-tester

   pathway / postgraduate / create-lead).
2. Điền 7 trường bắt buộc trong form (LastName, Email, MobilePhone,
   You are?, Ngày sinh, Tỉnh/Thành phố, Nguồn Lead).
3. Với APICreateLead, điền thêm "Interested Programme" (Product2 Id) ở
   phần "Thông tin bổ sung" nếu muốn test mapping Category/Campus Group.
4. Để test case "thiếu field", chỉ cần XÓA trắng 1 ô input tương ứng rồi
   bấm "Gửi request" - không cần sửa JSON bổ sung.
5. Đọc kết quả ở khung "Response" bên phải:
   - Badge xanh (HTTP 2xx) = thành công
   - Badge đỏ (HTTP 4xx/5xx hoặc có errorCode) = bị chặn/lỗi
6. Sau khi test xong, vào Salesforce (Setup > Object Manager > Lead > View
   Records, hoặc dùng SF CLI: sf data query --query "SELECT Id, LastName,
   You_are__c, RecordType.Name FROM Lead ORDER BY CreatedDate DESC LIMIT 10"
   --target-org DEV) để đối chiếu RecordType và dữ liệu đã lưu đúng chưa.
